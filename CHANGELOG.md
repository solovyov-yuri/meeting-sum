# Changelog

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии — по
[семантическому версионированию](https://semver.org/lang/ru/).

## [0.2.0] — 2026-08-08

Первый тегированный релиз. Содержимое собрано из истории после `05beb1e`; всё, что было до,
относится к нетегированной 0.1.0.

### Добавлено

- Саммари в десктопе теперь редактируется как готовый для Telegram простой текст: он же лежит в
  `.txt`, показывается в редакторе и копируется в буфер. CLI остаётся на Markdown. Сохранение и
  экспорт разбирают текст обратно, сами определяя форму, поэтому записи истории, созданные раньше,
  продолжают открываться.
- JSON-схема саммари действительно уходит в `response_format`. Провайдеры, которые её не принимают
  (старые сборки Ollama/lm-studio/vllm), получают один повтор с обычным `json_object`, и лишь затем
  включается текстовый фолбэк.
- Перед загрузкой библиотек CUDA приложение проверяет, есть ли в машине видеокарта NVIDIA:
  при `device: cuda` без карты — понятная ошибка вместо ~2 ГБ впустую, при `device: auto` — прогон
  на процессоре с явным предупреждением, а не молча. Аварийный тумблер — `RECAP_ASSUME_GPU`.
- Портативная сборка находит `ffmpeg.exe`, положенный рядом с приложением флагом `-Ffmpeg`, без
  ручной правки `PATH`.
- Журнал долга ручной проверки — `docs/manual-qa-pending.md`.

### Исправлено

- «Остановить» работает во время суммаризации: и в режиме «Повторить суммаризацию», и в полном
  прогоне. Отмена применяется, когда модель ответила, — саммари отбрасывается, транскрипт остаётся.
- Саммари больше не меняет структуру при сохранении и экспорте. Переводы строк внутри пункта не
  перетекают в прозу соседнего блока; метка списка в верхнем регистре (`ИТОГИ:`, `TODO:`) не читается
  как заголовок; проза, заканчивающаяся двоеточием, не съедается как метка; два соседних списка не
  склеиваются.
- Загрузка модели в Ollama не зависает навсегда на молчащем сокете, и «Отменить» на ней срабатывает.
- Экспорт при повреждённом `.json` идёт из текста, а не падает целиком; экспорт без единого
  пригодного источника завершается ошибкой до записи, а не четырьмя пустыми файлами.
- Долгоживущий воркер пишет в собственный `recap-bridge-serve.log`: раньше он и одиночные команды
  делили один файл, и ротация молча ломалась, пока приложение запущено.
- Кривой `cancel_flag` в запросе больше не роняет воркер вместе с прогретой моделью.
- Мост читает `stdin` как UTF-8, а не только пишет в UTF-8, — кириллица в пути больше не превращается
  в кракозябры при прямом запуске.
- При открытии записи истории подсвечивается тот шаг, который вообще виден в её режиме: упавший
  прогон «Саммари» или «Подготовка» больше не выглядит как «Ожидает».
- Отменённый прогон в браузерном моке завершается статусом `cancelled`, а не `success`.

### Безопасность

- Каждое скачанное CUDA-колесо проверяется по sha256 из ответа PyPI до распаковки.
- Член архива не может выйти за каталог кэша при распаковке DLL.
- Запись, инициированная из webview, скоуплена: `save_summary` перезаписывает только файл саммари из
  истории, а имя файла для экспорта обязано быть простым именем без переходов по каталогам.
- Загрузка модели идёт на адрес из сохранённых настроек, а не на присланный из webview.

### Производительность

- Распаковка CUDA-DLL идёт потоково, а не через чтение файла целиком в память, и опрашивает отмену.

### Прочее

- `pyinstaller` объявлен и запинен (`>=6,<7`) в группе зависимостей `packaging`; сборка ставит его
  через `uv sync --group packaging`.
- Тест ловит расхождение между пинами CUDA в `cuda_support` и разрешёнными в `uv.lock` версиями.
- `nvidia-cudnn-cu12` поднят до 9.24.0.43 вслед за локом.
- Документация приведена в соответствие с кодом: контракт моста, README, `--help`, спека, чеклист
  агента и карта модулей в `AGENTS.md`.
