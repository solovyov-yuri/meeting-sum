# Интеграция Recap с пользовательскими агентами

## Пользовательский сценарий

Пользователь устанавливает Recap, подключает его к локальному агенту и просит: «Сделай подробное
саммари этого видео через Recap». Агент обнаруживает типизированные инструменты, проверяет
готовность конфигурации, запускает обработку, отслеживает долгую задачу и возвращает саммари со
ссылками на transcript и структурированный JSON. GUI не обязан быть открыт.

Первая версия ориентирована на локальные agent-клиенты, способные запускать MCP stdio server или
локальный процесс. Облачный чат без доступа к файловой системе пользователя находится вне scope:
ему потребовался бы отдельный защищённый local-to-cloud connector.

## Публичная граница

Внутренний `recap-bridge` остаётся интерфейсом доверенного Tauri-shell и не публикуется целиком.
Отдельный `recap-agent` gateway предоставляет узкий набор инструментов:

- `get_status` — версия, возможности и готовность конфигурации без раскрытия секретов;
- `create_summary` — входной файл и per-run overrides, результатом является `job_id`;
- `get_job` — этап, прогресс, terminal status, безопасная ошибка и пути артефактов;
- `cancel_job` — кооперативная отмена;
- `get_result` — summary/transcript и ссылки на сохранённые форматы.

GUI и gateway используют один application service, app-data каталог, keychain, историю и worker.
Ошибка имеет стабильный machine code и отдельное человекочитаемое сообщение. Повторный запрос с
тем же idempotency key не создаёт второй дорогой run.

## Долгие задачи

Production-контракт оформляет транскрибацию как устойчивый job, который переживает перезапуск
agent-клиента. Per-user worker сериализует GPU-задачи, сохраняет состояние атомарно и удерживает
прогретую Whisper-модель. MVP может временно оборачивать существующий streaming bridge синхронно,
но не обещает reconnect до появления durable job service.

## Установка и обнаружение

Подписанный per-user installer устанавливает GUI, gateway/worker и ffmpeg в стабильный каталог.
Onboarding предлагает явные действия подключения к поддерживаемым клиентам; конфигурация сторонних
агентов не редактируется молча. Uninstall удаляет регистрацию и предлагает сохранить или удалить
пользовательские результаты и настройки отдельно.

## Приватность и полномочия

API-ключи остаются в OS keychain и никогда не передаются через tool arguments. При внешнем LLM и
отсутствии согласия gateway возвращает terminal `CONSENT_REQUIRED` до отправки транскрипта. Агент
может продолжить только после явного per-run или сохранённого пользовательского согласия.

Gateway не экспортирует произвольные команды внутреннего bridge и не предоставляет CRUD
API-ключей. Запись результатов ограничивается выбранным или настроенным output-каталогом.

## Критерии готовности

- После установки поддерживаемый локальный агент обнаруживает Recap без знания внутреннего пути к
  sidecar.
- `get_status` объясняет, готов ли Recap к run и какое действие требуется пользователю.
- Длинный run возвращает `job_id`, допускает status/cancel и не дублируется после reconnect.
- `partial_success` сохраняет transcript и позволяет повторить только суммаризацию.
- Внешний provider не получает transcript без зафиксированного согласия.
- Success, missing input, consent required, provider unavailable, partial success и cancel покрыты
  end-to-end fixtures.
- GUI и agent-run показывают одну историю и используют одни настройки и keychain.
