# REL-010: Логика on-demand CUDA не учитывает фактическое железо

## Проблема

`_ensure_cuda()` гейтится только на `sys.frozen and device == "cuda"`. Две симметричные дыры:

1. **device=cuda без NVIDIA GPU** (дефолт конфига — `"cuda"`, типичный корпоративный ноутбук без
   дискретной карты): первый запуск обязательным шагом скачает пиннованные cuBLAS+cuDNN (~700 МБ
   трафика, ~2 ГБ на диске), успешно поставит сентинел — а затем загрузка модели упадёт с сырой
   CUDA-ошибкой. Гигабайты впустую, повторные запуски продолжают падать, фолбэка на CPU нет.
2. **device=auto на GPU-машине** (evidence: hypothesis — нужно живое поведение ctranslate2):
   `_ensure_cuda` пропускается (`device != "cuda"`), DLL не скачаны → `auto` резолвится в CPU.
   Пользователь, выбравший «auto» в UI ожидая GPU, тихо получает медленную транскрибацию без
   какого-либо предложения докачать библиотеки.

## Доказательства

`src/workflows.py::_ensure_cuda` — условие видно в коде (2026-07-05); `config.py` — дефолт
`device: str = "cuda"`; `types.ts` предлагает `"auto"` в настройках UI. Пункт 2 подтвердит запуск
портативной сборки с `device: auto` на GPU-машине: лог покажет CPU и отсутствие шага `download`.

## Почему это важно

Это главный onboarding-путь портативной сборки — первая транскрибация нового пользователя. Для
заметной доли машин он либо гарантированно ломается после долгой загрузки, либо тихо деградирует
в CPU.

## Варианты решения

1. **(Рекомендуется)** Дешёвая проверка наличия GPU перед загрузкой: `ctypes.WinDLL("nvcuda.dll")`
   (драйвер NVIDIA ставит её в System32). Нет GPU + `device=cuda` → понятная ошибка с
   предложением переключить на `cpu`/`auto` **до** скачивания; есть GPU + `device=auto` + frozen →
   трактовать как cuda-кандидата и предлагать загрузку.
2. Продукт-решение (за владельцем): при отсутствии GPU автоматически падать в CPU-режим с
   warning-событием вместо ошибки.

## Как проверить исправление

Unit-тесты `_ensure_cuda` с замоканной GPU-проверкой (4 комбинации device×GPU). Вручную: portable
на машине без NVIDIA — шаг `download` не стартует; на GPU-машине с `auto` — загрузка предлагается.
