# DOC-004: Фичи последних трёх дней невидимы в пользовательской документации

## Проблема

- **Режим `lecture` («конспект»)** зарегистрирован в `SUMMARY_MODES`, `config.yaml.example` и UI,
  но: README (строки ~44, ~173 — таблица режимов, ~231), три help-строки CLI (`cli.py:97, 281,
  346` — `recap run -m lecture` работает, но из `--help` не виден) и `desktop-tauri-spec.md:230`
  перечисляют только `brief | medium | detailed`.
- **Расширения**: README «Поддерживаемые расширения: .wav, .mp3, .m4a, .ogg», а `AUDIO_EXTENSIONS`
  давно включает `.mp4, .mkv, .webm, .flac` (batch и десктоп их принимают).
- **Portable-сборка**: из README (раздел «Десктоп-приложение») недостижим `docs/portable-build.md`
  — grep по «portable/портатив» в README и desktop/README пуст; дистрибутив существует только для
  тех, кто знает о нём заранее.

## Доказательства

Grep-сверки агента DEP/CONV/DOC-прохода + чтение перечисленных строк (2026-07-05).

## Почему это важно

Это витрина проекта: пользователь CLI не откроет `prompts.py`, чтобы узнать о режиме; поддержка
`.mp4` была high-severity фиксом (REL-004), который README до сих пор отрицает.

## Варианты решения

1. **(Рекомендуется)** Однопроходная синхронизация: `lecture` в README-таблицу и три help-строки
   (или генерировать help из `SUMMARY_MODES`), список расширений из `AUDIO_EXTENSIONS`, строка со
   ссылкой на `docs/portable-build.md` в разделе «Десктоп-приложение», `lecture` в
   desktop-tauri-spec.
2. Радикальнее для help: `typer` choices из `SUMMARY_MODES` — не отстанет впредь.

## Как проверить исправление

`recap.exe run --help` показывает `lecture`; grep `mp4`/`portable-build` по README не пуст.
