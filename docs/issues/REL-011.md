# REL-011: Портативный ffmpeg вне зоны поиска CreateProcess

## Проблема

`build-portable.ps1 -Ffmpeg` копирует `ffmpeg.exe` в корень портативной папки рядом с `Recap.exe`,
но мост (`recap-bridge.exe` в подкаталоге `recap-bridge/`) вызывает голый `"ffmpeg"`
(`preprocessing.py`), а `bridge_command()` в Rust не модифицирует `PATH` дочернего процесса.
CreateProcess ищет в каталоге exe самого моста, cwd и PATH — корень портативной папки попадает в
поиск только если cwd случайно равен ему (запуск двойным кликом), и не попадает при запуске через
ярлык с другим «Start in». `docs/portable-build.md` честно требует «add the portable folder to
PATH» вручную — т.е. опция создаёт бандл, который сам по себе не работает.

## Доказательства

Пути и вызовы прочитаны в этом ревью (2026-07-05); признание в `docs/portable-build.md` (раздел
про ffmpeg).

## Почему это важно

Preprocessing в portable молча падает «ffmpeg не найден» у пользователя, который видел, что
ffmpeg.exe лежит рядом с приложением. Ломается ровно тот no-install сценарий, ради которого
сборка делалась.

## Варианты решения

1. **(Рекомендуется)** В `bridge_command()` дописывать каталог `Recap.exe` (и/или каталог
   bundled-моста) в `PATH` дочернего процесса — одна строка `cmd.env("PATH", …)`; закрывает
   вопрос без действий пользователя, dev-режим не трогает.
2. Альтернатива: в `preprocessing.py` резолвить ffmpeg через переменную `RECAP_FFMPEG`,
   выставляемую Rust-ом (больше движущихся частей).

## Как проверить исправление

`cargo.exe check`/`clippy` здесь; вручную на Windows — full-режим из портативной папки с
`ffmpeg.exe` рядом, запуск через ярлык с другим «Start in».
