# REL-005: write_text_atomic — fsync и уборка tmp

## Проблема

В `utils.py:14-28`: (а) cleanup (`tmp.unlink`) покрывает только неудачный `replace`, но не
неудачный `write` (диск полон → осиротевший `.name.*.tmp`); (б) нет `flush()+os.fsync()` перед
rename — при потере питания атомарный rename может закрепить пустой/усечённый файл.

## Варианты решения

1. **Рекомендуется:** одно try вокруг write+replace с unlink в except; `f.flush(); os.fsync(f.fileno())` перед выходом из `with`.
2. Принять как есть для локального инструмента и задокументировать.

## Как проверить исправление

Юнит-тест: исключение из `f.write` (mock) не оставляет tmp-файлов.
