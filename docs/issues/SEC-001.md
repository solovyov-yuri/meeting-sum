# SEC-001: Живой API-ключ в открытом виде в config.yaml

## Проблема

В `config.yaml` (строка 39, `summarization.model.api_key`) лежит действующий ключ формата
`sk-proj-…` в открытом виде. Ключ **не закоммичен** (файл в `.gitignore`, `git log --all --
config.yaml` пуст — проверено), но он читается любым инструментом/агентом/бэкапом/скриншерингом,
касающимся рабочей копии. В частности, его уже прочитали агенты этого ревью. `config.yaml.example`
(строка 39) активно предлагает класть ключ именно в этот файл.

## Почему это важно

Плейнтекст-секрет в корне проекта, с которым регулярно работают AI-агенты, — это утечка, ждущая
своего часа. Инфраструктура для безопасного хранения уже есть в проекте (`src/secrets_store.py`,
OS-keychain — используется десктопом).

## Варианты решения

1. **Сделать немедленно:** ротировать ключ на platform.openai.com и удалить строку из config.yaml; задать через `RECAP_SUMMARIZATION_MODEL_API_KEY` (env). Ноль изменений кода.
2. Переиспользовать `secrets_store.py` (keychain) и в CLI-пути — small, унифицирует CLI/десктоп.
3. Минимум: поменять рекомендацию в `config.yaml.example` на env-переменную, чтобы не воспроизводить привычку.

## Как проверить исправление

`grep -n "api_key" config.yaml` не находит значения; старый ключ отозван; `recap summarize` работает с ключом из env/keychain.
