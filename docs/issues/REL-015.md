# REL-015: Крайние ветки CUDA не проверены живыми Windows-прогонами

## Проблема

Две ветки CUDA покрыты автоматическими тестами, но ни разу не наблюдались в целевом runtime:
отмена уже во время распаковки второго пакета и поведение машины без NVIDIA. Для распаковки важно
не оставить completion sentinel после отмены; для машины без GPU — не скачать около 2 ГБ при
`device=cuda` и явно перейти на CPU с предупреждением при `device=auto`.

## Доказательства

На машине разработки есть NVIDIA. Ручной прогон 2026-08-08 подтвердил отмену загрузки, но не дошёл
до распаковки. Ветка отсутствия GPU проверялась только через mocks/override.

## Почему это важно

Ошибка проявится на первой установке или после удаления CUDA cache и может оставить гигабайты
неполных данных либо привести к неожиданно медленному CPU-run.

## Варианты решения

1. **Рекомендуется:** выполнить оба сценария по шагам ниже и записать результат в roadmap.
2. Автоматизировать Windows integration fixture с управляемым `RECAP_ASSUME_GPU`; отмена реальной
   распаковки всё равно останется отдельным packaging/runtime прогоном.

## Как проверить исправление

1. Удалить `%APPDATA%\app.recap.desktop\cuda`, начать GPU-загрузку и отменить на сообщении
   «Распаковка». Sentinel `.recap-cuda-complete` не создаётся, следующий запуск предлагает
   загрузку снова.
2. С `RECAP_ASSUME_GPU=0`: `device=cuda` завершается понятной ошибкой без загрузки,
   `device=auto` продолжает на CPU с явным warning.
