# REL-013: Нет фолбэка при повреждённом summary-.json в экспорте

## Проблема

`export_summary` уже предусматривает фолбэк на `parse_summary(summary_text)` — но только для
случая «валидный JSON без blocks» (старый формат). Если `.json` повреждён (обрезан при заполнении
диска, испорчен ручным редактированием), `load_summary_json` кидает `SummaryValidationError`,
которая пролетает до границы `main` — весь экспорт падает с «Невалидный JSON…», хотя валидный
Markdown-текст саммари лежит прямо в payload и фолбэк-ветка на него уже написана строкой ниже.

## Доказательства

`src/desktop_bridge.py::export_summary` (2026-07-05): `summary = load_summary_json(...)` без
try/except; фолбэк срабатывает только при `not summary.blocks`.

## Почему это важно

Пользователь с повреждённым `.json` не может экспортировать вообще ничего, хотя все данные для
экспорта есть; сообщение об ошибке говорит про JSON, а не про решение.

## Варианты решения

1. **(Рекомендуется)** Обернуть `load_summary_json` в
   `try/except SummaryValidationError: summary = None` — существующий фолбэк дальше всё сделает.

## Как проверить исправление

Unit-тест: битый `.json` + валидный `summary_text` в payload → экспорт успешен, файлы отрендерены
из Markdown.
