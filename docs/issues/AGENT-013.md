# AGENT-013: Verification-контур честный, но без бухгалтерии

## Проблема

Граница WSL/Windows означает, что каждое desktop-изменение уходит «runtime-неверифицированным».
Honesty-правило требует это **проговаривать**, но нигде не **накапливает**: долг растёт молча,
пока пользователь сам не спросит. Наблюдалось в истории: сессия `9803cc1c` (04.07) — «Уже много
ходов накопилось десктоп-функций, которые ни разу не запускались вживую на Windows. Кратко опиши:
функция — что сделать, чтобы проверить»; ранее `427ae7bd` — «Возможно что-то из этого уже
поправилось — проверь». Вспоминать, что уже проверялось, тоже приходится пользователю.

## Почему это важно

Единственная систематическая дыра в остальном образцовом verification-контуре: о фиче, которую
забыли до следующего ручного прогона, false-negative никто не поймает.

## Варианты решения

1. **(Рекомендуется)** Checked-in `docs/manual-qa-pending.md`: агент обязан дописывать строку
   «фича → как проверить» при каждом runtime-неверифицированном изменении (правило — одна строка
   в AGENTS.md рядом с honesty-правилом); пользователь вычёркивает после прогона. Органично
   совмещается с реанимацией чеклиста ([[AGENT-012]]).
2. Вести в memory — хуже: Codex и другие машины не увидят.
3. Статус в commit-сообщениях — теряется при накоплении.

## Как проверить исправление

После следующей desktop-фичи файл пополнился без напоминания; запрос «что проверить вживую»
закрывается чтением файла.
