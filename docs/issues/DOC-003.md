# DOC-003: Контракт моста неполон для кода трёхдневной давности

## Проблема

`docs/desktop-bridge-contract.md` — заявленный источник истины для Rust/TS/Python
(«Types mirroring docs/desktop-bridge-contract.md» в `types.ts:1`). Реализация уехала вперёд:

- §2 перечисляет шаги `preprocess, transcribe, summarize, export`, но workflow эмитит пятый —
  `download` (CUDA-загрузка и Ollama-pull; `STEP_DOWNLOAD` в `workflows.py`, `StepName` в
  `types.ts` уже включает `"download"`). Комментарий в `workflows.py:44` («kept in sync with
  docs/desktop-bridge-contract.md») уже неверен.
- §4 не знает три команды: `save_summary` (сохранение отредактированного саммари), `check_model`
  (преф-чек Ollama-модели), `pull_model` — причём последняя — третий стриминговый канал со своим
  событием `model-pull-progress`.
- Мелочи: пример `get_settings` без `output_dir` и `api_keys_configured` (фактически
  возвращаются); `test_connection` описан как «проверяет доступность», хотя реализация намеренно
  офлайн; в примере `max_transcript_chars: 60000` при дефолте `42_000`.

## Доказательства

Сверка списка `_STREAMING_COMMANDS` + веток `main()` в `desktop_bridge.py` с §4 контракта; в
Rust `generate_handler!` — 16 команд (2026-07-05).

## Почему это важно

Прошлое ревью уже чинило ровно это ([[DOC-001]]); документ снова перестал быть контрактом через
три дня. Новые интеграции и агенты будут писаться по неполному документу. Повторение намекает на
процессную дыру — см. [[AGENT-009]] (обновление доков не входит в definition-of-done фичи).

## Варианты решения

1. **(Рекомендуется)** Дописать `download` в §2 и разделы `save_summary`/`check_model`/`pull_model`
   в §4 по образцу соседних (вход/выход/стриминг/семантика отмены), поправить пример
   `get_settings`.
2. Минимум — сноска «полный список см. desktop_bridge.py» (хуже: документ перестаёт быть
   контрактом).

## Как проверить исправление

Каждая команда из `generate_handler!` в `lib.rs` и каждая ветка диспетчера `main()`/`serve()`
имеет раздел в §4; список step в §2 совпадает с `STEP_*`-константами `workflows.py`.
