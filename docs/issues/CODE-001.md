# CODE-001: Пути вывода десктопа хардкодятся рядом с аудио

## Проблема

`useRecap.ts` (`start`, ~166-167) выводит `transcript_path = ${dir}/${base}.txt` и
`summary_path = ${dir}/${base}_summary.txt` из брошенного аудиофайла, игнорируя настроенные
пользователем пути `transcript`/`summary` (которые экран «Пути» в настройках позволяет
редактировать).

## Почему это важно

1. Существующий `meeting.txt` (например, собственные заметки пользователя рядом с `meeting.mp3`)
   перезаписывается без предупреждения — тихая потеря данных в правдоподобном сценарии.
2. Раздел «Пути» в настройках фактически декоративен для десктоп-запусков — сбивает с толку.

## Варианты решения

1. **Рекомендуется:** по умолчанию писать результаты в каталог данных приложения (или в настроенные пути), а рядом с аудио — только по явному экспорту; опционально настройка «писать рядом с исходником».
2. Минимум: не перезаписывать существующие файлы (суффикс `-1`, `-2` или подтверждение).

## Как проверить исправление

Положить рядом с аудио файл `{stem}.txt` со своим содержимым, запустить обработку — файл не перезаписан молча.
