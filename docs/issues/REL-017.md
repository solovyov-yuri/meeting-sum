# REL-017: UTF-8 stdin bridge не проверен в чистом PowerShell

## Проблема

`_force_utf8_io()` переконфигурирует stdin, но исправление проверено только тестовым потоком.
Прямой запуск frozen `recap-bridge.exe` с кириллическим путём и без UTF-8 environment не выполнялся.
Основной Tauri-путь менее уязвим: Rust выставляет `PYTHONUTF8=1`.

## Доказательства

Ручной QA 2026-08-08 оставил этот отладочный сценарий непроверенным. Код и unit test существуют,
поэтому риск ограничен прямым использованием bridge вне приложения.

## Почему это важно

Ошибка даст mojibake или `UnicodeDecodeError` для кириллического `audio_path` в диагностическом и
будущем agent-facing использовании bridge.

## Варианты решения

1. **Рекомендуется:** выполнить один прямой PowerShell smoke run и закрыть issue при корректном
   round-trip пути.
2. Добавить subprocess integration test на Windows locale; дороже низкого риска сценария.

## Как проверить исправление

В чистом PowerShell без `PYTHONUTF8`/`PYTHONIOENCODING` передать UTF-8 JSON с кириллическим
`audio_path` в `recap-bridge.exe run_recap`. Ответ содержит исходный путь без mojibake и traceback.
