# Ревью 2026-08-30 — agent-first интерфейс Recap

## Скоуп и метод

Фокусированный запуск по продуктовому сценарию: пользователь устанавливает Recap и просит своего
локального агента сделать саммари видео. Проверены реальные entry points и CLI help, Python
bridge/worker, Tauri host, state/keychain boundary, portable packaging и документация.

## Итог после классификации

Первоначально наблюдения были разложены на пять issue-кандидатов: публичная agent API boundary,
durable jobs, installer/discovery, consent boundary и integration documentation. При последующей
ревизии структуры work record установлено, что все пять описывают части одной возможности, которой
продукт ещё не обещал и не реализовывал, а не дефекты относительно принятого поведения.

Новых issue этого review-run: **0**. Материал сохранён как
[proposal 0001 — «Интеграция Recap с пользовательскими агентами»](../proposals/0001-agent-integration.md).
Это сохраняет анализ, но не заставляет severity выполнять роль продуктового приоритета.

## Рекомендуемая последовательность proposal

1. Зафиксировать публичную tool schema и error taxonomy.
2. Сделать MCP/JSON MVP поверх текущего application core с блокирующим consent boundary.
3. Добавить installer integration и end-to-end fixtures.
4. До production-обещания длинных runs оформить worker как durable job service.

## Сильные стороны, которые нужно сохранить

- `workflows.RunResult` уже даёт `success`, `partial_success`, `failed`, `cancelled` и recovery без
  повторной транскрибации.
- Bridge выдаёт NDJSON progress и структурированные пути артефактов.
- Секреты находятся в OS keychain и не попадают в settings/history/logs.
- Cooperative cancellation и warm Whisper worker являются хорошей базой job service.
- GUI и Python core разделены; gateway может быть тонким adapter.

Интеграции с реальными agent-клиентами не создавались и не проверялись.
