# REL-006: Гонка в history.json

## Проблема

Каждая команда моста — отдельный процесс (spawn per call в `lib.rs`). `_append_history` и
`delete_history_item` делают `read → modify → write` без файловой блокировки: завершение запуска,
совпавшее с удалением записи (или вторым запуском), теряет одну из записей. Масштаб ущерба —
только метаданные истории.

## Варианты решения

1. Файловая блокировка (`msvcrt.locking` / `portalocker`) вокруг read+write — small.
2. Принять риск (одно окно, худший случай — потерянная строка истории) и зафиксировать решение.

## Как проверить исправление

Тест с двумя конкурентными вызовами `_append_history` — обе записи на месте.
