# SEC-005: Тесты не изолированы от RECAP_*-env — красный сьют + утечка живого ключа в вывод pytest

## Проблема

`Settings.load()` штатно подхватывает `RECAP_*`-переменные окружения при каждом вызове, а тесты
дефолтов (`tests/test_config.py::test_defaults_produce_nested_settings`, строка
`assert s.summarization.model.api_key is None`) не очищают окружение. `tests/conftest.py` не
существует вовсе — env-скраббинга нет нигде.

На машине пользователя выставлена `RECAP_SUMMARIZATION_MODEL_API_KEY` (ровно так, как рекомендует
`config.yaml.example` после SEC-001), поэтому:

1. полный сьют падает: `1 failed, 349 passed`;
2. **полное значение живого OpenAI-ключа печатается открытым текстом в assert-diff pytest** —
   в консоль, в CI-логи, в вывод любых агентов, запускающих тесты.

## Доказательства

- Прогон `.venv/Scripts/pytest.exe -q` в этом ревью (2026-07-05): `1 failed, 349 passed`,
  падение именно в `test_defaults_produce_nested_settings`, в diff — значение ключа `sk-proj-…`
  (в отчёте не воспроизводится).
- `ls tests/conftest.py` → файла нет.
- Ирония: `config.yaml.example` сам предписывает задавать ключ через эту переменную, т.е.
  задокументированная конфигурация гарантированно ломает сьют.

## Почему это важно

Нарушается собственное правило проекта «secrets never reach logs» — транзитивно, через тестовый
вывод. Ключ уже был напечатан в логи процессов этого ревью → его следует считать засвеченным.
Плюс сьют красный на любой машине, настроенной по инструкции, что обесценивает сигнал тестов
(агенты и человек начинают игнорировать «известное падение»).

## Варианты решения

1. **(Рекомендуется)** Autouse-фикстура в новом `tests/conftest.py`, удаляющая все `RECAP_*` из
   окружения перед каждым тестом (через `monkeypatch.delenv`/фильтрацию `os.environ`). Плюс
   **ротировать засвеченный ключ** на platform.openai.com.
2. Точечный `monkeypatch.delenv("RECAP_SUMMARIZATION_MODEL_API_KEY", raising=False)` в
   падающем тесте — закрывает симптом, не класс проблем (любой новый `RECAP_*` снова уронит сьют).
3. Убрать ключ из пользовательского env (только keychain) — не защищает других разработчиков/CI.

## Как проверить исправление

```bash
RECAP_SUMMARIZATION_MODEL_API_KEY=test-not-a-key .venv/Scripts/pytest.exe -q  # → 0 failed
```
(из WSL переменную надо прокинуть в Windows-процесс, надёжнее проверить на Windows-стороне).
Плюс подтверждение ротации ключа.
