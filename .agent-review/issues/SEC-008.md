# SEC-008: Zip-slip при распаковке CUDA-wheel

## Проблема

`_extract_dlls()` пишет члены архива как `target = dest / name` без нормализации. Фильтр
`parts[0] == "nvidia" and "bin" in parts and name.endswith(".dll")` пропускает имя вида
`nvidia/../../../x/bin/evil.dll` — запись уйдёт за пределы `dest`.

Эксплуатируется только злонамеренным wheel-ом, т.е. в связке с [[SEC-006]] (нет проверки хэша):
вместе они позволяют подложить DLL в произвольный каталог. Как самостоятельная дыра — низкая
(PyPI + HTTPS), как defense-in-depth — стоит закрыть одновременно с SEC-006.

## Доказательства

`src/cuda_support.py`, `_extract_dlls` (прочитан 2026-07-05):

```python
target = dest / name
target.parent.mkdir(parents=True, exist_ok=True)
```

## Почему это важно

Второй слой защиты той же единственной точки, где проект скачивает исполняемый код. Дешёвый фикс,
устраняющий целый класс последствий компрометации канала загрузки.

## Варианты решения

1. **(Рекомендуется)** Перед записью проверять
   `target.resolve().is_relative_to(dest.resolve())` (и/или отвергать `..` в `parts`);
   нарушение → `RuntimeError`.

## Как проверить исправление

Unit-тест: zip с членом `nvidia/../outside/bin/x.dll` → исключение/пропуск, за пределами `dest`
ничего не создано.
