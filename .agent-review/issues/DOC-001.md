# DOC-001: Контракт моста отстал от реализации

## Проблема

§4 контракта документирует 8 команд, реализация (`desktop_bridge.py:~448-505`, `lib.rs:~254-267`,
всего 12 Tauri-команд) содержит ещё `test_connection`, `read_text`, `resummarize`, `cancel_run`.
`grep -rn "resummarize|test_connection|read_text" docs/` — ноль совпадений. `desktop/README.md`
упоминает `test_connection`/`read_text`, но не `resummarize`, хотя фронтенд его вызывает
(`bridge.ts:32, 65-68`) и это второй **стриминговый** канал (README утверждает, что стримит только
`run_recap`). При этом resummarize — ядро recovery-пути partial_success, который UX-спека считает
ключевым состоянием (`desktop-tauri-spec.md:~175-178`).

## Почему это важно

Контракт — заявленная спецификация интерфейса frontend/backend («kept in sync», коммент в
`workflows.py:34`); агент, реализующий по нему, пропустит recovery-путь.

## Варианты решения

1. Дописать §4: `test_connection`, `read_text`, `resummarize` (вход/выход JSON, отметка про стриминг) и фактическую семантику `cancel_run` (согласовать с решением по [[ARCH-002]]).

## Как проверить исправление

Каждая команда из `main()` моста имеет секцию в контракте; README десктопа упоминает оба стриминговых вызова.
