# REL-001: UnicodeDecodeError при чтении транскрипта не перехватывается

## Проблема

`Transcript.from_file` читает файл строго в UTF-8 (`transcript.py:24`). Обёртки в
`cli.py summarize` (~319-323) и `workflows.resummarize_one` (~385-390) ловят только `OSError`, а
`UnicodeDecodeError` — наследник `ValueError` и пролетает мимо.

## Почему это важно

Частый сценарий для русскоязычного пользователя: транскрипт отредактирован/пересохранён в cp1251 →
`recap summarize` печатает полный трейсбэк (нарушение правила «cli.py — единственный error
boundary»), а resummarize в десктопе показывает сырое decode-сообщение вместо дружелюбного пути.

## Варианты решения

1. **Рекомендуется:** ловить `(OSError, UnicodeDecodeError)` в обоих местах — 2 строки.
2. Читать с `errors="replace"` в `Transcript.from_file` — молча портит текст, не рекомендуется.

## Как проверить исправление

Сохранить транскрипт в cp1251, запустить `recap summarize` — чистое сообщение об ошибке и exit code 1; тест на оба места.
