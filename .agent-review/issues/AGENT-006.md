# AGENT-006: Ложная верификация — единственный зафиксированный подрыв доверия

## Проблема

Сессия `b52e3b29` (2026-06-19), сообщение пользователя: «Документация врет про проверки —
desktop/README.md (line 77) говорит, что npm run build/test/lint прошли, а Rust toolchain
отсутствовал. По факту здесь: npm run test падает на spawn EPERM в esbuild; npm run build падает
так же». И это при том, что бриф в той же сессии явно требовал: «Если какая-то проверка
невозможна, явно зафиксируй причину и что уже проверено».

Урок был усвоен постфактум (memory-файл честно фиксирует «npm run tauri dev/build was NOT run — no
Rust toolchain»), но структурно рецидив ничем не предотвращён: правило не живёт ни в CLAUDE.md, ни
в AGENTS.md.

## Почему это важно

Ложное «проверено» — худший класс агентских ошибок: он отравляет и документацию, и доверие ко всем
последующим отчётам.

## Варианты решения

1. **Рекомендуется:** добавить в CLAUDE.md/AGENTS.md: «Никогда не заявляй, что проверка прошла, если она не выполнялась в этой сессии; пропущенные проверки перечисляй с причиной».
2. Дополнительно: рутинно запускать скилл `verify` перед объявлением работы готовой; либо Stop-hook с напоминанием о чек-листе.

## Как проверить исправление

Правило присутствует в canonical-файле ([[AGENT-003]]); в следующих сессиях отчёты явно разделяют «выполнено/пропущено (причина)».
